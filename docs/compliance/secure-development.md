## איך שינוי עולה לאוויר (A.8.32)

1. שינוי נכתב במחשב הפיתוח (בעזרת Claude Code). פיצ'ר חדש עובר את התהליך שב-`CLAUDE.md`: מפרט, ניסוי קטן, תוכנית, בנייה ובדיקה, סקירה.
2. `npm run verify` במחשב: lint, כל הבדיקות, בדיקת טיפוסים, בנייה.
3. דחיפה ל-GitHub. GitHub Actions מריץ שוב את `npm run verify` ואת `npm audit --omit=dev --audit-level=high` (`.github/workflows/verify.yml`).
4. Vercel בונה ומפרסם מ-`master`. כל גרסה ניתנת להחזרה ב-Instant Rollback.

**חסר (בקרת פיצוי לאדם אחד):** אין סקירה של אדם שני ואין חסימה של `master` עד ש-CI עובר. מומלץ להפעיל ב-GitHub ← Settings ← Branches ← כלל ל-`master` שדורש שבדיקת `verify` תעבור. החיסרון: כל שינוי צריך לעבור דרך Pull Request.

## כללי קוד מאובטח (A.8.28)

- כל endpoint של מנהל מתחיל ב-`requireManager()`; פעולת בעלים בודקת `isOwner`. כל POST בודק Origin.
- כל קלט מהרשת נקרא עם מגבלת גודל (`readJson`) ונבדק לצורה; קובץ גיבוי ותשובות טפסים הם "לא אמינים".
- אין `innerHTML`, `eval` או `dangerouslySetInnerHTML`; CSP חוסם סקריפטים חיצוניים. כל מקור חיצוני חדש נוסף במפורש ל-`connect-src` ב-`vercel.json`.
- כל מה שנשמר בשרת עובר `seal()`. סודות רק מ-`process.env`.
- כל קריאה בתשלום עוברת `spendGuard` (רק על Vercel). אין שימוש במפתח האמיתי בפיתוח.
- כל פעולה רגישה חדשה (גישה, הרשאות, מפתחות) נרשמת ביומן האבטחה (`audit()` ב-`api/_lib/audit.ts`).
- הגבלת ניסיונות לכל endpoint ציבורי (`api/_lib/rate.ts`).

## בדיקות (A.8.29)

- בדיקות אוטומטיות לשרת (`api/_lib/*.test.ts`), כולל: אין כניסה בלי אימות, קוד פעם אחת, הבעלים בלבד, יומן אבטחה, החלפת מפתח.
- סריקות קוד תקופתיות ב-`docs/reviews/` (האחרונה 2026-11-10).
- **חסר:** בדיקת חדירות (penetration test) על ידי גורם חיצוני. מומלץ לפני מבדק התעודה.

## חבילות צד שלישי (A.8.8)

- `npm audit` חוסם חולשה חמורה ב-CI. Dependabot פותח עדכונים שבועיים (`.github/dependabot.yml`).
- מוסיפים חבילה רק אם אין דרך פשוטה בלעדיה. `package-lock.json` נשמר ב-git.
