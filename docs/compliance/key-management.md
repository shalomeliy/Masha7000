## איך מחליפים את `SESSION_KEY` בלי לנתק את כולם

החל מ-2026-11-13 השרת יודע לפתוח ערכים ישנים במפתח הקודם (`SESSION_KEY_PREVIOUS`), ומצפין כל ערך חדש במפתח החדש.

1. ליצור מפתח חדש במחשב:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
   ```
2. ב-Vercel ← Settings ← Environment Variables (Production): להעתיק את הערך הנוכחי של `SESSION_KEY` למשתנה חדש בשם `SESSION_KEY_PREVIOUS`.
3. לשים את המפתח החדש ב-`SESSION_KEY`.
4. Redeploy. מעכשיו: כניסות, אימות דו-שלבי, קודי גיבוי וחיבור Drive ממשיכים לעבוד. כל ערך שנשמר מחדש מוצפן במפתח החדש (טוקן Drive מוצפן מחדש בבקשה הראשונה).
5. אחרי 180 יום (משך כניסה מקסימלי) למחוק את `SESSION_KEY_PREVIOUS` ולעשות Redeploy.
6. לרשום ב"יומן הבקרה" (`isms-scope.md`): תאריך, סיבה.

**מה לא עובר את ההחלפה:** hash של טלפון ות"ז בטופס ההצטרפות (בדיקת כפילות) מחושב עם המפתח החדש, כך שמצטרף שנרשם לפני ההחלפה ונרשם שוב לא יזוהה ככפילות. השפעה זניחה.

**אם המפתח דלף:** לא לחכות 180 יום. להחליף לפי השלבים, ובשלב 5 למחוק את `SESSION_KEY_PREVIOUS` מיד. כולם יתבקשו להתחבר מחדש ולהגדיר אימות מחדש, והבעלים יחבר Drive מחדש. זה המחיר של מפתח שדלף. לטפל כאירוע לפי `incident-response.md`.
