# נוהל טיפול באירוע אבטחה

טיוטה 0.1, 2026-11-13 (A.5.24 - A.5.28, A.6.8, ISO 27017 CLD.16.1.7 הנחיות). **מאושר: ______**

## מה נחשב אירוע

כל דבר שמאיים על סודיות, שלמות או זמינות של מידע: מפתח או סיסמה שדלפו; כניסה חשודה ביומן האבטחה; נתונים שהשתנו או נמחקו בלי הסבר; דיווח מחוקר אבטחה (`/.well-known/security.txt`); הודעה מספק על אירוע אצלו; טלפון או מחשב של המפעיל שאבד; האתר לא זמין יותר משעה.

## איך מדווחים אלינו

- מנהל, עובד או חוקר: מייל לכתובת שב-`security.txt` ובדף הפרטיות. עונים תוך 5 ימי עבודה (בפועל: אירוע חמור, באותו יום).
- המפעיל: כל מה שהוא רואה בעצמו נרשם כמו דיווח.

## השלבים

**1. לרשום (מיד).** פותחים שורה בטבלה למטה: מתי התגלה, מי דיווח, מה ידוע. לא מוחקים שום ראיה (יומן אבטחה, Sentry, Vercel logs: לצלם או לייצא).

**2. להעריך (תוך שעה).**

| רמה | דוגמה | זמן תגובה |
|---|---|---|
| חמור | מידע אישי של עובדים יצא החוצה; מישהו זר נכנס כמנהל; `SESSION_KEY` דלף | מיד |
| בינוני | מפתח API או טוקן ספק דלף בלי סימן לשימוש; ניסיונות כניסה רבים | אותו יום |
| נמוך | שגיאה בלי השפעה על מידע; דיווח שלא אומת | תוך שבוע |

**3. לבלום.** לפי מה שקרה:

| מה קרה | מה עושים | איפה |
|---|---|---|
| מנהל נפרץ או טלפון אבד | הסרה מהרשימה (מנתק ומוחק אימות) או איפוס אימות | הגדרות ← גישה |
| הבעלים נפרץ | ניתוק מכל המכשירים; ניתוק Drive; החלפת סיסמת Google ובדיקת "Security" בחשבון Google | הגדרות ← אבטחה / ← גישה |
| `SESSION_KEY` דלף | החלפה מיידית, בלי מפתח קודם (`key-management.md`) | Vercel |
| טוקן ספק דלף | ביטול אצל הספק ויצירה מחדש ב-Vercel, Redeploy | אצל הספק |
| מפתח API חיצוני דלף | ביטול המפתח | הגדרות ← גישת API |
| קוד זדוני עלה | Vercel ← Deployments ← Promote את הגרסה התקינה האחרונה ("Instant Rollback") | Vercel |
| חיבור Drive מוזר | ניתוק Drive, ב-Google: myaccount.google.com/permissions להסיר את האפליקציה | |
| כל השירות בסכנה | Vercel ← Settings ← לכבות את הפרויקט (Pause) | Vercel |

**4. לחקור ולתקן.** מה הסיבה? איזה מידע, של אילו לקוחות? לתקן בקוד (עם בדיקה שמונעת חזרה), ולעדכן את רשימת הסיכונים.

**5. להודיע.**

- **ללקוח** (בעל השליטה במאגר): על כל אירוע חמור או בינוני שנוגע לנתונים שלו, בהקדם, עם מה ידוע, מה נעשה, ומה הוא צריך לעשות. הלקוח הוא שמדווח לרשות כבעל המאגר; אנחנו עוזרים לו.
- **לרשות להגנת הפרטיות:** לפי תקנות הגנת הפרטיות (אבטחת מידע) התשע"ז-2017, אירוע אבטחה חמור במאגר מדווח לרשות **מיד**. לבדוק עם עורך דין מי חייב לדווח (הלקוח, אנחנו, או שנינו) ובאיזה נוסח, **לפני** שקורה אירוע.
- **GDPR** (אם יש לקוח באירופה): לרשות הפיקוח תוך 72 שעות.
- לספק, אם האירוע אצלו או דרכו.

**6. ללמוד (תוך שבועיים).** מה עבד, מה לא, מה משתנה. אירוע חמור עולה בסקר ההנהלה.

## ראיות (A.5.28)

שומרים לפחות שנתיים: הייצוא של יומן האבטחה, צילומי Sentry ו-Vercel, מיילים, ומה נעשה ומתי. בתיקייה מחוץ לחשבונות שנפגעו.
