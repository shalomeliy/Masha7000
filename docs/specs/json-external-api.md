# מפרט: נתונים ב-JSON מתועד + API חיצוני (גרסה הבאה)

סטטוס: אושר ונבנה (2026-11-11). תוכנית: docs/plans/json-external-api-PLAN.md. תיעוד: docs/api.md. `SECURITY TRIGGERED`: נבדק על ידי `security-expert` לפני המיזוג.

## מה קיים היום (נבדק בקוד)

- **כל הנתונים כבר שמורים כ-JSON.** 17 קבצים בתיקייה החבויה של האפליקציה ב-Google Drive של הבעלים (`DRIVE_FILES` ב-`src/lib/google/config.ts`): עובדים, הסמכות, תבניות עבודה, עבודות ממתינות, מקומות, סוגי עבודה, מחלקות, הגדרות, הערות ודוגמאות של Shaly, הגייה ועוד. משמרות שמורות קובץ לכל חודש (`shifts-2026-11.json`, `src/lib/data/shiftMonths.ts`).
- המבנה של כל רשומה מוגדר ב-TypeScript (`src/types/models.ts`), אבל אין לו מספר גרסה ואין מסמך שמישהו מבחוץ יכול לקרוא.
- הדפדפן קורא וכותב ל-Drive ישירות. השרת (Vercel) כבר מחזיק את ה-refresh token של הבעלים, ונותן ממנו access token למנהלים מחוברים (`api/token.ts`). כלומר לשרת כבר יש דרך טכנית לקרוא את הנתונים.
- כל `/api` של מנהל עובר דרך `requireManager()`: עוגייה + אימות דו-שלבי. זה מתאים לאדם בדפדפן, לא למערכת אחרת.
- אין היום שום API שמערכת חיצונית יכולה לקרוא ממנו.

**האמת:** "שכל המערכת תיבנה על JSON" כבר קרה. מה שחסר זה (1) חוזה JSON קבוע ומתועד, ו-(2) דלת מבחוץ.

## מה משתנה

### חלק א: חוזה JSON (שינוי קטן, בלי שינוי חוויה)

- קובץ `schema-version` בתוך הנתונים, ומספר גרסה (`"schemaVersion": 1`) בכל תשובת API.
- JSON Schema מתועד לכל ישות שנחשפת החוצה: עובד, משמרת, עבודה ממתינה, הסמכה, אילוץ. נוצר מה-TypeScript הקיים, כך שאין שתי הגדרות שנפרדות.
- שמות שדות באנגלית, תאריכים `YYYY-MM-DD`, זמנים ISO. ה-API מחזיר צורה נקייה ויציבה, לא את הקובץ הגולמי (שדות ישנים כמו `roleId` לא יוצאים החוצה).

### חלק ב: API חיצוני

בסיס: `https://masha7000.vercel.app/api/v1/...`

שלב 1, קריאה בלבד (מוצע):

| נתיב | מה מחזיר |
|---|---|
| `GET /api/v1/workers` | עובדים פעילים: מזהה, שם פרטי ושם משפחה, הסמכות + כוכבים + תוקף, סטטוס, מחלקה |
| `GET /api/v1/shifts?from=2026-11-01&to=2026-11-30` | משמרות בטווח: תאריך, סוג, מקום, תיאור, צוות, איוש, סגירה |
| `GET /api/v1/pending-jobs` | עבודות שממתינות לשיבוץ |
| `GET /api/v1/certifications` | רשימת ההסמכות |
| `GET /api/v1/schema` | ה-JSON Schema וגרסתו |

שלב 2, כתיבה (המשתמש ביקש קריאה וכתיבה, 2026-11-11): `POST /api/v1/pending-jobs` (עבודה ממתינה חדשה), `POST /api/v1/shifts` ו-`PATCH /api/v1/shifts/<id>` (משמרת חדשה, שינוי צוות או פרטים), `PATCH /api/v1/workers/<id>` (סטטוס, הסמכות, תוקף), `POST /api/v1/workers/<id>/constraints` (אילוץ). מחיקה: לא בשלב הזה. כל כתיבה נבדקת מול אותם כללים של האפליקציה (הסמכה מתאימה, בלי עובד כפול) ונרשמת ביומן. כתיבה מבחוץ מתנגשת עם שמירה מהאפליקציה באותו קובץ, ולכן משתמשת באותה בדיקת התנגשות שיש היום (`ConflictError`) ומחזירה `409` כשמישהו שמר באמצע.

### הרשאות (auth) ל-API

- **מפתח API** שהבעלים יוצר בהגדרות > "גישת API": שם למפתח (למשל "דוחות שכר"), הרשאות (קריאה / כתיבה), ואילו נתונים מותר.
- המפתח מוצג פעם אחת בלבד. בשרת נשמר רק ה-hash שלו (Upstash, כמו שאר הסודות).
- נשלח בכותרת `Authorization: Bearer <key>`. בלי עוגיות, בלי דפדפן.
- ביטול מפתח בלחיצה, מיידי. רשימת מפתחות עם "שימוש אחרון".
- הגבלת קצב לכל מפתח (למשל 60 בקשות בדקה), ותיעוד כל קריאה (מפתח, נתיב, זמן) בלי תוכן הנתונים.
- רק הבעלים יוצר ומבטל מפתחות. מנהלים אחרים לא.
- ה-API לא קורא ל-Anthropic בכלל, ולכן לא נוגע ב-`spendGuard` ולא עולה כסף של Claude.

### פרטיות

ברירת מחדל: **בלי** ת.ז, מספר אישי, כתובת, תאריך לידה וטלפונים. אפשר לפתוח אותם רק במפתח שסומן במפורש "כולל פרטים אישיים", עם אזהרה.

## מה לא בגרסה הזו

- מעבר מ-Google Drive למסד נתונים (נשארים על Drive, כמו שהוחלט).
- Webhooks (מערכת חיצונית מקבלת הודעה כשמשהו משתנה). אפשרי בהמשך.
- גישה לעובדים עצמם דרך ה-API.
- סנכרון Google Calendar.

## הסיכון הגדול, ולכן ספייק קודם

כל קריאת API תפתח את ה-Drive של הבעלים מהשרת. לא ידוע עדיין כמה זה מהיר (משמרות של שנה = 12 קבצים) והאם זה עומד במגבלות של Google ושל Vercel. ספייק קטן: נתיב אחד `GET /api/v1/shifts` עם מפתח קבוע, מודד זמן תשובה. יעד: עד 2 שניות לחודש, עד 5 שניות לשנה. אם לא עומד, מוסיפים מטמון קצר בשרת.

## קריטריוני קבלה

1. בלי מפתח, או עם מפתח מבוטל: `401`. מפתח קריאה שמנסה לכתוב: `403`.
2. מפתח בלי "פרטים אישיים" לא מחזיר אף אחד מהשדות האישיים, בשום נתיב.
3. `GET /api/v1/shifts?from&to` מחזיר בדיוק את המשמרות שהאפליקציה מראה באותו טווח.
4. מעבר למגבלת הקצב: `429`.
5. ביטול מפתח עובד תוך שנייה, בלי לחכות.
6. התיעוד (`/api/v1/schema` + דף הסבר קצר) מספיק כדי שמתכנת מבחוץ יוציא רשימת עובדים בלי לשאול שאלות.
