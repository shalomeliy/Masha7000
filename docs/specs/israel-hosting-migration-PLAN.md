# תוכנית מעבר: Google Cloud בתל אביב, ה-AI באירופה, Whisper בישראל

טיוטה, 2026-11-28. **תוכנית בלבד, עוד לא העברנו כלום.** הבעלים אישר את הכיוון ב-28.11.2026.
המחקר שמאחורי התוכנית: `/mnt/project-files/reports/israel-hosting-voice-research.md` (ועליו `cloudflare-migration-research.md`). התוכנית מרחיבה את `docs/specs/israel-region.md`, שבו שלב 1 כבר מפורט עם הערכת זמן.

מקרא: **[ידיים שלך]** = רק הבעלים יכול לעשות את השלב (חשבון, תשלום, כניסה, החלטה). **[Claude]** = קוד ותיעוד, נעשה בסשן. **[ביחד]** = Claude מכין, הבעלים לוחץ או בודק.

## שאלות פתוחות (לפני שלב 4)

1. **האם "בישראל" באמת חייב?** לפי מה שאני מבין, חוק הגנת הפרטיות (כולל תיקון 13) מתיר להעביר מידע למדינות האיחוד האירופי, כך ש"בישראל" היא דרישה של לקוחות מסוימים (ביטחון, ממשלה) ולא של החוק. לא בדקתי את זה מול עורך דין. **[ידיים שלך]**: לשאול עורך דין או לקוח יעד. התשובה קובעת אם צריך את שלב 6.
2. **המשמרות: נשארות ב-Drive או עוברות ל-Firestore בתל אביב?** ב-Drive כל מנהל מחזיק את הנתונים שלו, אבל הם לא בישראל. ב-Firestore בתל אביב הכול בישראל, אבל אתה מחזיק את הנתונים של כל הלקוחות במקום אחד, ומקבל יותר אחריות לפי תיקון 13 ו-ISO. זה גם בערך 8 שבועות עבודה. **[ידיים שלך]**. שלבים 0 עד 5 לא תלויים בתשובה.

### שלב 2: ה-AI עובר ל-Vertex EU, עוד ב-Vercel (בערך 3 ימים) **[Claude]**

- [ ] **[ידיים שלך]**: ליצור ב-Google Cloud חשבון שירות עם הרשאת Vertex בלבד, ולשים את המפתח שלו ב-Vercel. מכינים הוראות מדויקות מראש.

### שלב 3: השרת והמאגר עוברים לתל אביב (בערך 3 שבועות קלנדריים) **[Claude]**

הפירוט וההערכה (7.5 ימי עבודה + שבוע הרצה כפולה) נמצאים כבר ב-`israel-region.md`, סעיף 1. בקצרה:

- [ ] שרת Node קטן שמריץ את `api/_lib/router.ts` ואת הכותרות (CSP, HSTS) מתוך `vercel.json`. ה-handlers כבר בנויים כ-`Request -> Response`.
- [ ] `api/_lib/kv.ts` על Firestore `me-west1`, באותו ממשק (get/set/NX/EX/incr/lists). את התפוגה הקוד בודק בעצמו, כי Firestore מוחק פגי-תוקף באיחור של עד 24 שעות.
- [ ] `spendGuard.ts`: היום הוא בודק `VERCEL=1`. צריך בדיקה מקבילה ל-Cloud Run (למשל `K_SERVICE` ועוד משתנה שלנו), **בלי להחליש אותה**, עם בדיקה שנכשלת מקומית.
- [ ] Dockerfile, ופריסה מ-GitHub Actions ל-Cloud Run בלי מפתח קבוע (Workload Identity Federation).
- [ ] `max-instances=3` כתקרת עלות. בלי מופע ער תמיד, אלא אם תבחר אחרת (החלטה 3 ב-`israel-region.md`, בערך $10 לחודש).
- [ ] סודות ב-Secret Manager במקום משתני סביבה של Vercel.
- [ ] כלי העברה חד-פעמי מ-Upstash ל-Firestore: רשימת מורשים, 2FA, מפתחות API, טפסים ויומנים. סשנים לא מעבירים, כל אחד נכנס שוב פעם אחת.
- [ ] `tenancy.test.ts`, `router.test.ts` ו-`functionCount.test.ts` מתעדכנים. מגבלת 12 הקבצים של Vercel כבר לא רלוונטית.
- [ ] **[ידיים שלך]**: להעביר את הסודות (OAuth secret, `SESSION_KEY`, Resend, Sentry, `CLAUDE_LOG_TOKEN`) ל-Secret Manager. Claude לא רואה ערכים, רק נותן רשימת שמות.
- [ ] **[ידיים שלך]**: להוסיף ב-Google OAuth את המקור החדש ואת כתובת ה-callback.
- [ ] הרצה במקביל שבוע, כש-Vercel נשאר גיבוי חי.
